# Identification rules

What the pipeline is allowed to conclude about a feature's isotopes, halogens,
molecular formula, and charge state, and on what evidence. Written down because
the rules are currently spread across a vendored application, a portable scoring
layer, and a data file, and because several of them do not do what their names
suggest.

Every rule has an identifier, the statement, the constants, where it lives, and a
status. Cite the identifier when changing one.

| Status | Meaning |
|---|---|
| **Enforced** | Runs on the delivered path and can change an answer. |
| **Enforced upstream** | Implemented and correct in `vendor/nce/`, but only reachable through the full NCE elucidation application, not through `run_inference.sh`. |
| **Recorded only** | The evidence is captured in a column or a label, and nothing reads it. |
| **Inert** | The code runs, but on the delivered inputs it cannot change any answer. |
| **Absent** | Not implemented. Listed because its absence is a decision, not an oversight to be discovered twice. |

Counts quoted below come from
[docs/paper/data/identification/audit_identification_rules.md](paper/data/identification/audit_identification_rules.md),
regenerated by `tools/audit_identification_rules.py` from the committed feature
rows. The improvement plan built on them is
[plans/identification_rules_hardening.plan.md](../plans/identification_rules_hardening.plan.md).

## Conventions

**Polarity comes from the library, never from the spectrum.** Libraries 209 and
305 are negative mode, 400 and 402 positive
(`structural_elucidation/nce/evidence.py:47`, `vendor/nce/elucidation/chemFacts.py`).

**The forward equation.** An ion of charge `z` formed from `n` copies of a
molecule of neutral monoisotopic mass `M` appears at

```
m/z = (n*M + gains - losses + isotope_shift - s*z*m_e) / z
```

where `s` is +1 for cations and -1 for anions, `gains` and `losses` are neutral
atom masses, and `isotope_shift` is the extra mass carried by any heavy isotopes
in the ion. Inverting it is what turns an observation into a neutral-mass
hypothesis. The pipeline implements only the `n = z = 1`, no-gain, no-shift case
of it; every rule below that concerns charge is a statement about that
restriction.

**Two proton conventions coexist** and agree to 1.4e-8 Da: 1.007276466812
(`nce/evidence.py:45`) and 1.007276 (`utils/phase0.py:39`). Precursors are
neutralized with the proton mass, MS2 fragments with the electron mass
(`evidence.neutral_ion_mass`).

## Charge and adduct rules (CHG)

### CHG-1 — Polarity is a library property

Negative for lib 209/305, positive for 400/402. Any other id raises rather than
guessing. `chemFacts.molecular_ion_name`, `evidence.lib_ion_mode`.

**Status: enforced.**

### CHG-2 — The neutral mass assumes a singly charged monomer

`M = m/z + proton` in negative mode, `M = m/z - proton` in positive. No charge
state, multimer count, adduct, or isotope shift enters the conversion.
`evidence.neutral_mass_from_precursor`, `phase0.neutral_mass_from_precursor`,
`chemFacts.neutralize_precursor_mz`.

**Status: enforced.** This is the rule that actually governs every delivered
neutral mass, which is why CHG-4 matters.

### CHG-3 — The phase-0 ladder is the only adduct enumeration in the package

Candidate mass matching (phase-0 reconstruction and analog prefilter/`mass_match`)
shares one table: [`data/adducts/adduct_ladder.csv`](../data/adducts/adduct_ladder.csv),
loaded by `chemistry/adduct_ladder.py`. Defaults are `[M+H]+` / `[M-H]-`. Every
Excel Adducts-sheet monomer is an `offset` row (`M = mz - mz_minus_M`). Four
`legacy_phase0` extras keep the old dimer / `z=2` arithmetic with
`phase0.PROTON_MASS = 1.007276`. `platform_hint` is stored (`pos` / `neg` /
`polar`) but not filtered. `[M+CH3COO]-` is **not** in the Excel sheet and is
not on the ladder.

`best_adduct_neutral_mass_match` still retries each table adduct at 0, 1, and 2
carbon-13 shifts (`C13_SHIFT_MASS = 1.003355`). Cl37 is a named adduct row, not
an extra isotope axis. Excel Cl / formate offsets differ by ~0.5–2 mDa from the
old hardcodes 34.969402 / 44.998201; the table values win.

**Status: inert on the delivered path.** Do **not** rerun `run_inference.sh` to
“identify” Excel adducts. That script never reads `data/adducts/adduct_ladder.csv`
(`ADDUCT_LADDER` points at `chrolib_adduct_ladder.csv` and is unused). Ranking
and `mass_match_score` stay `[M±H]` (CHG-2). Default `START_AT=verifier` does not
even rebuild candidates.

Callers of the table today: `reconstruct_shortlisted_candidates` and analog
`mass_match` / prefilter. Analog pools **will** see a wider closest-adduct match
**only if you regenerate them** (`python -m structural_elucidation.evaluation.analog`).
Pass `--drop-polar-adducts` on libs 209/305 if Cl/formate over-assign. Compound
reports annotate `hypothesized_adduct` / `adduct_mass_error_da` from
`best_adduct_neutral_mass_match` without changing `mass_match_score`.

To put adducts on the identification path, run candidates with
`--derive-neutral-mass-from-adduct` (default **off**), then **candidates → verify
→ pool → rerank**, and a paired McNemar on truth controls
(`tools/audit_mass_policy.py --rerank`). Inventory first:
`python3 tools/inventory_adduct_ladder.py`. Do not mix the Biotransformations or
Isotopes workbook sheets into this ladder (conjugates stay in
`chemistry/conjugates.py`; ¹³C overlay stays in `best_adduct_neutral_mass_match`).
`closest_neutral_mass` still discards the adduct argument and returns `[M±H]`.

### CHG-4 — The delivered adduct ladder is recorded, not applied

`data/feature_rows/*_neutral_mass_hypotheses.csv` carries 10,568 hypotheses over
4,483 features, with 489 distinct ion labels covering protonation, sodiation,
dimers, doubly charged anions, neutral-gain clusters, and isotopologues. Each row
also carries a `charge` and a `multiplier` column, and those columns are right:
they agree with the ion named in the label on all 5,988 rows where both are
populated.

The stored `neutral_mass` does not use them. Re-deriving each row's neutral mass
from its own label gives:

| Ion family | Rows | Follows its own label | Median error vs its label |
|---|---:|---:|---:|
| `protonated` | 1,839 | 1,839 | 0.0000 Da |
| `isotopologue` | 2,707 | 0 | 1.0035 Da |
| `multimer` | 450 | 0 | 144.83 Da |
| `multiply_charged` | 269 | 0 | 458.27 Da |
| `adduct_or_cluster` | 292 | 0 | 21.98 Da |
| `numeric_offset` | 431 | 0 | 62.996 Da |
| `consensus_or_fallback` | 4,535 | n/a | no derivation stated |

10,534 of 10,568 rows (99.7%) carry the neutral mass of a singly charged,
monomeric, monoisotopic protonation whatever ion their label names. The ladder
widens the *target list* by a few milli-daltons of jitter and by nothing else.

**Status: recorded only.** The consequence is that CHG-2 is not a default that a
richer hypothesis can override; it is the only rule in force.

### CHG-5 — `recomputed_mz` is an echo, not a round trip

The column equals `parent_mz` exactly on 8,774 rows, is blank on 1,794, and
disagrees on none. It is not recomputing the m/z from the stored neutral mass
under the row's own charge and multiplier, so it agrees unconditionally and would
have agreed just as readily with any of the wrong masses in CHG-4.

**Status: inert.** A round trip that cannot fail is not a check.

### CHG-6 — Charge state is never inferred

Nothing measures isotope-envelope spacing to determine `z`. A doubly charged
precursor is read as singly charged and lands at half its true neutral mass.

The audit helper `charge_state_suspects` in `tools/audit_mass_policy.py` still
runs after delivery. The same integer-ratio test now **caps MSI Level 1 or 2 at
Level 4** in `reports/confidence.py` (`charge_ratio_label`) when
`observed_neutral_mass` and `candidate_exact_mass` are present. That does not
infer `z`; it only withholds a probable/confirmed structure claim.

**Status: inference absent; MSI cap enforced** when both masses are on the
confidence fields. Background in `docs/mass_axis_decisions_needed.md`.

## Isotope rules (ISO)

### ISO-1 — What counts as an isotope peak

A co-eluting MS1 peak is an isotope buddy when its mass difference from the
feature matches a tabulated isotope delta within **2 ppm** (default), it appears
in at least **10%** of the feature's MS1 spectra, and in more than one spectrum.
Unlabelled leftover peaks need **25%** of spectra and a coefficient of variation
below **0.25**, and only the ten best are kept. The final table drops anything
with `|delta| <= 0.1 Da`.

Multiplicity cascades: `[X-2]` is rejected unless `[X-1]` was also found, and
`[X-3]` unless both were (`ms1Analyzer.is_good_isotope`).

Tracked isotopes: `13C`, `37Cl`, `81Br`, `34S`, `18O`, `15N`, and deuterium.
`vendor/nce/elucidation/ms1Analyzer.py:89-183`.

**Status: enforced upstream.**

### ISO-2 — Heavy-atom count from the intensity ratio

`count = observed_ratio / natural_abundance_ratio`, using the abundances embedded
in `chemFacts._abundance_ratio_dict`, and accepted only inside a per-element
window (`ms1Analyzer.add_prediction`):

| Element | Accepted window | Effect |
|---|---|---|
| C | 0.5 to 80 | usable |
| Cl | 0.5 to 3 | usable |
| Br | 0.5 to 3 | usable |
| S | 0.5 to 3 | usable |
| O | -2 to -1 | **never accepted** |
| N | -2 to -1 | **never accepted** |

The oxygen and nitrogen windows are negative and a ratio-derived count is not, so
no oxygen or nitrogen count is ever produced. The code comment (`# no O, N.`)
confirms this is deliberate: at natural abundance their M+1 and M+2 contributions
are not separable from the carbon envelope.

When the feature is itself the heavy peak ("is" rather than "has"), the reciprocal
ratio is used. Deuterium is detected but never counted, because it is
artificially introduced and has no natural-abundance baseline.

**Status: enforced upstream.**

### ISO-3 — A formula must contain the atoms its isotopes imply (NCE)

Given counts from ISO-2, a candidate formula survives only if
`|C - Ĉ| <= 4`, `|Cl - Ĉl| <= 0.5`, `|Br - B̂r| <= 0.5`, and, when a 34S peak was
seen at all, `|S - Ŝ| <= 0.5`. Sulfur is conditional because 34S does not always
appear; the halogens are not, because 37Cl and 81Br always do.
`ms1Analyzer.is_formula_isotopically_ok`.

**Status: enforced upstream, and skipped for X compounds.** The filter is applied
in `feature.complete_candidate_fmlas` only when `discoverer_version !=
"IonTracker"`, and `X_elucidator.py:109` sets exactly that value for every
X-compound run. The entire population this repository works on bypasses it.

### ISO-4 — A formula must contain the atoms its isotopes imply (portable)

The portable restatement: for every element hinted by an isotope label, the
candidate formula must carry at least that many atoms of it. Failing this is
`formula_impossible`, which is terminal rather than scored.
`utils/html.formula_satisfies_isotope_hints`, `utils/html.audit_candidate_formula_against_html_signals`.

Note the difference from ISO-3: this is a floor (`>= k`), not a two-sided window.
A formula with ten chlorines satisfies a one-chlorine hint.

**Status: enforced, when it has input.** See ISO-8.

### ISO-5 — Isotope intensity ratios are scored, not just checked

Expected relative intensity of the M+k isotopologue is binomial in the element
count:

```
expected = C(count, k) * (a / (1 - a))^k
score    = max(0, 1 - |ln(observed / expected)| / ln 3)
```

so the score reaches zero at a threefold error in either direction, and
`score >= 0.5` is reported as `ratio_supported` against `ratio_mismatch`
otherwise. Abundances `a` are hard-coded in `utils/html.ISOTOPE_ABUNDANCE`:

| Isotope | `a` | Isotope | `a` |
|---|---|---|---|
| 13C | 0.0107 | 15N | 0.00364 |
| 18O | 0.00205 | 37Cl | 0.2422 |
| 34S | 0.0421 | 81Br | 0.4931 |

Per-formula scores are averaged over the observed isotope rows.
`utils/html.expected_isotope_ratio`, `isotope_ratio_score`.

**Status: enforced, when it has input.**

### ISO-6 — A feature that is itself an isotopologue is flagged, not dropped

A buddy label beginning `x[` (or `feature[` / `self[` under the
`correct_isotopologue_detection` switch), or a comment matching "isotope of",
"potential overlap ... isotope", or "appears to be ... isotope", marks the
feature as a likely isotopologue. The audit status becomes `feature_isotopologue`
and short-circuits ratio scoring. `utils/html.detect_feature_isotopologue_reason`.

**Status: enforced, when it has input.**

### ISO-7 — What the pool does with the verdict

`formula_impossible` candidates are dropped outright
(`pipeline/pool_v1.py:383-388`, `--isotope-filter-impossible`, default on). Every
other status becomes two features of the reranker, `isotope_formula_score` and
`isotope_ratio_score`, each defaulting to **0.5** when isotope data is absent
(`pool_v1.py:304-313`, `rerank.py:76-77`).

**Status: enforced.**

### ISO-8 — The only input path is a delivered HTML report

Everything in ISO-4 through ISO-7 is fed by `parse_html_signals`, which reads a
per-feature NCE elucidation HTML page named by the `source_html` column
(`inference/predict.py:1021-1091`). `run_inference.sh` never passes
`--isotope-signals-csv` to the pool stage, so on the shipped path every candidate
takes the 0.5 prior and the `formula_impossible` filter drops nothing.

Meanwhile the committed adduct ladder carries the same evidence in a form nothing
parses: isotope tokens in `adduct_label` and in the consensus `note` give element
hints for **2,115 of 4,483 features (47%)** — 2,088 carbon, 620 oxygen, 167
sulfur, 45 nitrogen, 18 chlorine, 5 bromine.

**Status: the rules are enforced; the evidence is recorded only.** This is the
single cheapest gap on this page to close.

## Halogen rules (HAL)

There is no halogen detector. Halogens are a consequence of the isotope rules and
of what the formula enumerator was allowed to build.

### HAL-1 — Chlorine and bromine are inferred from their isotope peaks alone

37Cl and 81Br sit at M+2 with abundance ratios near 0.32 and 0.97, which is what
makes them visible at all, and ISO-1 and ISO-2 detect and count them like any
other isotope. No mass-defect test, no Kendrick analysis, and no halogen-specific
scoring exists anywhere in the repository.

**Status: enforced upstream (ISO-1/ISO-2), recorded only on the delivered path
(ISO-8).**

### HAL-2 — Fluorine and iodine cannot be inferred at all

Both are monoisotopic, so they produce no isotope peak and no ratio. They enter
only by appearing in an enumerated formula (HAL-3) and are never evidenced. A
prediction containing fluorine is asserting it from the mass and the generative
model, not observing it.

**Status: absent by physics, and worth stating in any report that names a
fluorinated candidate.**

### HAL-3 — The formula enumerator admits at most one halogen species

The precomputed formula tables allow C 0-55, H 0-94, N 0-11, O 0-22, S 0-2, plus
**one** option drawn from a single mutually exclusive slot. As the builder is
committed
(`vendor/nce/elucidation/table_builders/formula_finder_builder.py:99-121`) that
slot is `{Cl, Cl2, P, P2, I, F, F2, F3, Br, ClF3}`; the `ClF3` entry is a
hand-added exception "to help with drugs".

Consequences to know before reading a formula list as exhaustive: no formula can
contain both chlorine and bromine, none can contain three chlorines or two
bromines, and none can contain both phosphorus and a halogen.

Two documented descriptions of this slot disagree with the code and with each
other. `formulaFinder.py:30-37` lists `Br, Br' ([81Br]), Cl, Cl2, F, F2, I, P,
P2` — including a separate 81Br option the builder does not emit and omitting F3
and ClF3 — and the builder's own printed summary says `P 0-3` where the code
passes 2. The tables themselves are fetched pickles, not committed, so which of
the three the shipped cache was built from is not determinable from this
checkout.

**Status: enforced upstream, with the exact slot unverifiable here.**

### HAL-4 — The MS2 halogen filter is keyed on a name nothing writes

`ms2Ion.py:115-118` discards every fragment formula containing Cl or Br unless
`iso_count["[Cl37-1]"]` or `iso_count["[Br81-1]"]` is non-zero. The producer,
`ms1Analyzer.analyze_isotopes`, writes those counts under the bare isotope names
`"Cl37"` and `"Br81"` (`ms1Analyzer.py:280,293`). `iso_count` is a
`defaultdict(int)`, so the bracketed lookups return 0 unconditionally.

Every chlorinated and brominated fragment formula is therefore discarded on every
feature, including features with strong halogen isotope evidence.

**Status: enforced upstream, and inverted.** The rule as intended is sound; the
key does not match.

### HAL-5 — Halogens count as half a ring-or-double-bond each

Monovalent, so each contributes `(1 - 2) / 2 = -0.5` to the DBE of FML-3 and
`-hal/2` to the portable proxy of FML-6, and they count as heteroatoms in that
proxy's heteroatom-to-carbon ratio.

**Status: enforced.**

### Coverage

20 features across 19 controls in the committed feature rows carry direct
halogen isotope evidence. That is small enough that sampling it away loses all of
it, and specific enough that each one is checkable by hand.

## Formula rules (FML)

### FML-1 — The formula space is a box fitted to the reference library

C 0-55, H 0-94, N 0-11, O 0-22, S 0-2, plus one halogen or phosphorus option per
HAL-3. About 44 million formulas, of which fewer than 39 million fall below
1000 Da. The bounds were chosen to cover nearly every formula already in the
library, not from a chemical principle.
`table_builders/formula_finder_builder.py`.

**Status: enforced upstream.** Anything outside the box is unreachable, which
matters most for sulfur: two is a low ceiling for a matrix containing
disulfates.

### FML-2 — Formula lookup runs at 5 ppm

`FormulaFinder.fmlas_for_neutral_mass` defaults to 5 ppm, as does library ion
matching (`binning.within_5ppm`). This is the only tolerance on this page that
matches the instrument.

**Status: enforced upstream.**

### FML-3 — Ring and double-bond equivalents must be positive and whole

Computed on the neutralized formula (`neutralize_fmla` moves the charge onto
hydrogen) as `sum(count * (valence - 2)) / 2 + 1` over C, H, F, Cl, Br, I, N, P,
S, D, with **maximum** valences deliberately: `C 4, H 1, F 1, Cl 1, Br 1, I 1,
N 3, P 5, S 6, O 2, D 1`. Phosphorus at 5 and sulfur at 6 are what let phosphates
and sulfates through; nitrogen is held at 3 rather than 5 because 5 admitted too
many false positives.

The filter applied is `dbe > 0 and dbe == int(dbe)`
(`feature.get_candidate_fmlas:115`), which is stricter than
`chemFacts.is_good_dbe` (`>= 0`) — so a saturated acyclic formula with DBE 0 is
accepted by the predicate but rejected by the pipeline that calls it.

**Status: enforced upstream.**

### FML-4 — Element ratios are scored by a trained outlier model

`FormulaScorer.fmla_harmony` is a local-outlier-factor model over CHON count and
mass ratios, capped at 10, and formulas scoring at or below 1 are discarded
(`feature.get_candidate_fmlas:119-120`).

**Status: enforced upstream.** Needs the fetched `harmony.pkl`.

### FML-5 — Isotope consistency

ISO-3.

### FML-6 — The portable harmony proxy

The trained model is not portable, so `nce/evidence.formula_harmony_score`
substitutes a deterministic product of penalties. It starts at 1.0 and
multiplies:

| Condition | Factor |
|---|---|
| No carbon | 0.45 |
| H/C outside 0.2 to 3.4 | 0.55 |
| (N+O+P+S+halogens)/C above 2.6 | 0.65 |
| O above `max(4C + 4, 12)` | 0.70 |
| DBE below -0.5 | 0.35 |
| DBE in [-0.5, 0) | 0.70 |
| DBE above `max(30, C + 6)` | 0.75 |
| Mass error 0.01-0.1 / 0.1-1.0 / above 1.0 Da | 0.92 / 0.72 / 0.35 |

DBE here is `C - H/2 + N/2 + 1 - hal/2`, which omits phosphorus and sulfur and so
is not the same quantity as FML-3.

**Status: enforced.** This, not FML-4, is what runs on the delivered path.

### FML-7 — The formula prior

`0.65 * harmony + 0.35 * mass_fit`, with `mass_fit` a linear decay to zero at
0.05 Da by default (`chemistry/formula.formula_prior_score`).

**Status: enforced.**

### FML-8 — Mass tolerance is not one number

Four different windows are in force depending on which code path a candidate
came through:

| Window | Where | Applies to |
|---|---|---|
| 5 ppm | `formulaFinder`, `binning.within_5ppm` | NCE formula lookup, library ion match |
| 10 ppm, floor 0.005 Da | `phase0.strict_tolerance_da` | de novo shortlist reconstruction |
| plateau 0.001 Da, zero at 0.005 Da | `inference/mass_windows.py` | `predict.mass_match_score` |
| 1.0 Da, linear, no plateau | `chemistry/conjugates.linear_mass_match_score` as called by `pipeline/candidates.py` | most of the delivered `mass_match_score` column |

The last of these produced roughly 80% of delivered scores and is about 3,300 ppm
at these masses. This is measured and argued in
[docs/mass_axis_decisions_needed.md](mass_axis_decisions_needed.md); it is
recorded here only so that a reader of the formula rules does not assume the
5 ppm of FML-2 is what a candidate was judged against.

**Status: enforced, inconsistently.**

### FML-9 — What is deliberately not implemented

- **Senior's rules** (valence sum even, valence sum at least twice the maximum
  valence, at least `2(atoms - 1)`). Not present. FML-3's integrality test catches
  the first of the three and nothing catches the others.
- **Lewis octet rules.** Not present.
- **The Kind-Fiehn seven golden rules** as a set. FML-1, FML-3, FML-4 and ISO-3
  cover element restrictions, RDBE, element ratios, and isotope agreement; the
  hydrogen-count rule, the element-probability heuristic and the TMS rule have no
  equivalent.
- **Mass-defect filtering** of any kind.
- **Full isotope-envelope fitting.** ISO-5 scores each isotopologue peak
  independently against a binomial expectation rather than fitting the envelope.

**Status: absent.** Listed so the gap is a decision on the record.

## How the rules reach a reported level

The confidence model has five axes — structure 0.40, mass 0.30, MS2 0.20, pathway
0.10, retention 0.05, the last allowed to lower a score and not to raise it —
Platt-scaled on 92 truth-verified controls (`reports/confidence.py:33`, `:524`).
**No isotope, halogen, formula-plausibility or charge-state term appears in any of
them.** Isotope evidence reaches the answer only through the pool filter and the
two reranker features of ISO-7; formula plausibility only through FML-7 feeding
candidate generation.

The MSI level is then assigned from those axes with these boundaries:

| Constant | Value | Gates |
|---|---:|---|
| `MASS_STRONG` | 0.90 | Level 2, and the "strong mass" label |
| `MASS_WEAK` | 0.50 | demotion to Level 4 on mass mismatch |
| `STRUCT_MODERATE` | 0.70 | Level 2 |
| `STRUCT_WEAK` | 0.45 | Level 3 |
| `MS2_PRESENT` | 0.30 | Level 2 for a de novo candidate |
| `MS2_PROBABLE_EXACT` | 0.50 | Level 2 for a catalog hit |
| `RETENTION_IMPLAUSIBLE_Z` | 3.0 | rejection on retention |

Level 1 requires a Metabolon Level-1 standard match; a refuting human or
laboratory verdict in `data/curation_ledger.csv` caps the level at 4 regardless of
the axes. Levels 4 and 5 report a formula or a mass and withhold the structure —
which is the one place a formula rule directly determines what a reader sees.

## Reproducing the counts

```bash
python3 tools/audit_identification_rules.py
python3 -m pytest tests/test_identification_rules.py -q
```

Read-only, standard library only, and reproducible from committed inputs, so it
runs in the CI regenerate-and-diff step. Rules whose status is *enforced upstream*
cannot be checked this way: they need the vendored NCE caches, which are fetched
rather than committed.
